Read this before you start

Three things are true right now that the code will not tell you.

CI cannot start, and it is not the workflow file

Owner action

Every GitHub Actions run returns startup_failure in 0s with no jobs, no logs and an empty workflow name. This was bisected, not guessed: a six-line workflow with nothing in it to get wrong failed identically, and GitHub's own dynamic Copilot workflow — which nobody here authored — fails the same way. The Actions policy is clean (enabled, allowed_actions=all). The repository is private, so the likely cause is exhausted Actions minutes or a $0 spending limit. Confirming needs the billing scope; raising a limit is the owner's call. Until then the Definition-of-Done gates are local-only.

A screening turn takes about 91 seconds

Measured, unsolved

Not a hang and not a bug in the pipeline — see the latency section below for what was ruled out and, more importantly, for the one optimisation that must not be retried.

The knowledge base contradicts its own test cases

Clinical sign-off

Two red-flag rules grade three of the dataset's own gold-standard conversations wrong, and the test suite cannot currently see it. The engineering fix is clear; the content fix is a clinician's decision, not a developer's.

The response delay

Roughly 45s per LLM call. A normal turn makes two calls — observation, then risk reasoning — so the caretaker waits about 91 seconds. The final turn of a session adds a third call for the explanation.

Pipeline stage Calls logged Prompt size Runs on
Observation 15 ~364 tok every turn
Risk reasoning 15 ~1,328 tok every turn
Explanation 3 ~487 tok final turn only

Ruled out by measurement, not by argument. The prompts are small and the outputs are short JSON, so neither prompt size nor generation length accounts for 45 seconds. What remains is the model's own internal reasoning or queueing on the provider's side. A single timed curl straight at the provider separates those two, and that is the next step — it has not been run yet.

Do not re-attempt: per-tier max_tokens caps

This was tried and it broke the pipeline outright. deepseek-v4-flash spends its token budget on internal reasoning, so a 400-token ceiling left nothing for the reply and the model returned an empty string — AgentContractError on the very first turn. It is reverted. MAX_TOKENS_BY_TIER deliberately remains in the code but empty, with the reason recorded at its definition and a test asserting the field is omitted rather than sent as null. A cap is a guess about one model's reasoning overhead, and guessing low destroys the turn instead of shortening it.

The lever that has not been pulled

TIER_CHEAP, TIER_MID and TIER_STRONG exist and ride along every call, but nothing maps a tier to a model — one model currently serves all three. Observation is a structured-extraction task and does not need the same model as risk reasoning. Wiring the tiers is the realistic path to a faster turn, and it is blocked only on someone choosing the model names.

Also relevant: LLM_TIMEOUT_SECONDS is now a setting at 90s. A hardcoded 60s was previously killing turns outright.

One recommendation was made and then withdrawn. Moving the explanation call off the critical path looked attractive until the usage ledger was checked: only 3 of 33 calls were explanations. It would speed up the last turn of a session while leaving every follow-up turn at 91 seconds — real complexity and a new failure mode for a narrow win.

Knowledge base audit

94 rows — 50 milestones, 42 red flags, 2 risk modifiers; 61 Speech & Language, 33 Hearing. Provenance is recorded per row: 31 Ayesha original, 18 Ayesha original — CORRECTED, 45 Added in validation.

“Any caretaker concern” grades everything HIGH

Clinical sign-off

SL-RF-022 and HEAR-RF-014 are both severity HIGH, both span ages 0–72 months, and both have an empty follow-up question. Sourced to JCIH 2019 — which was written for a parent walking into a clinic, where “I'm worried” already means evidence has accumulated. SIGNAL opens because someone is worried, so the same sentence cannot carry the same weight.

Case Caretaker's opening line Expected Rule gives
T3 · 18mo “He only says about 5 words, is that bad?” LOW HIGH
T7 · 30mo “Sometimes I feel she's behind the other kids” LOW HIGH
T8 · 5yr “Something feels off with her” MODERATE HIGH

The provenance settles which side should give way: all three conversations are Ayesha original — CORRECTED, the domain lead's own gold standard, while both rules were Added in validation. Content added during validation is contradicting the domain lead's own cases.

Connected symptoms are counted as independent evidence

R14 · tracked

HEAR-RF-007 (ear-pulling with stalled speech), HEAR-RF-010 (sits close to the TV) and HEAR-RF-016 (recurrent ear infections) are all MODERATE and all in the Hearing domain. ADR-06 rule 1b reads ≥2 MODERATE red flags within the same domain → HIGH, so any two of them escalate. Clinically these are very likely one picture — fluid in the middle ear — not three findings. This is already logged as R14 with an xfail test pinning the divergence, and is explicitly blocked on clinical sign-off; no speculative fix is permitted.

28 of 42 red flags have no follow-up question

Content

These are exactly the moments where the agent should ask a clarifying question and instead has nothing to work from. Note that this is the same fix as the finding above it: SL-RF-022 and HEAR-RF-014 cannot become follow-up gates until their questions are written.

Two other gaps, both content

Content
  • Both risk modifiers are Hearing. Speech & Language has none — prematurity, NICU stay and family history of language disorder are all absent.
  • Only 13 of 94 rows name a year or edition in their source; 16 say bare “ASHA”. CDC shifted its milestone ages in 2022, and there is no way to tell which rows predate that.

Two claims that were checked and did not hold

An external review raised seven issues. Five are confirmed above. Two are not accurate, and a handover should say so rather than pass them along:

  • “No record of who added each row.” The CSV has a provenance column and it is fully populated. What is genuinely missing is a date and a named reviewer, not the origin.
  • “No ‘this looks fine’ outcome is a design oversight.” It is a deliberate ADR-06 decision, documented in grade(): the floor for the weakest confirmed evidence is LOW_MONITOR. There are also four states, not three — INSUFFICIENT_INFORMATION exists. Changing this needs a new ADR; existing ADRs are never overridden in place.
New finding, not in the external review. The dataset's expected_grade column is asserted only for the safeguarding cases and for T6 (the R14 xfail). It is not checked for the rest — which is precisely why the T3/T7/T8 contradiction has gone unnoticed. A detector test that runs every case through grade() and compares against expected_grade would turn this class of problem into a build failure instead of something a person has to spot. That work is pure engineering and needs no clinical input; the content decisions above still do.

Landed recently

Three PR review findings, all of the same shape as the original security audit: a control correct in intent and quietly wrong in code.

PHI was being written to logs

Fixed

Agent JSON parse failures logged a 120-character prefix of the model's output — which carries caretaker text and a child's clinical detail. The diagnostic value was never the content but the shape (empty means the token budget was spent before any output; prose means the JSON contract was ignored — opposite fixes). A classifier now reports the shape and the content never reaches a handler.

Tenant isolation could revert silently

Fixed

get_tenant_db fell back to DATABASE_URL when TENANT_DATABASE_URL was unset — and that is the privileged path by definition, so forgetting one setting reverted the entire row-level-security fix with no external symptom. It now refuses both a missing URL and any role reporting rolsuper or rolbypassrls, verified once per engine. There is deliberately no environment exemption: an exemption is how the control came to be inert the first time.

Unknown cost was reported as zero

Fixed

estimated_cost is nullable on purpose — an STT provider test hits a genuinely free endpoint and records 0, while an LLM test connection is a real billed call whose price cannot be computed and records NULL. Five call sites collapsed that distinction. Sums also skip NULLs, so a partial total read as a finished bill; the console now reports unpriced calls alongside the figure.

Standing it up on a new machine

Only PostgreSQL is containerised — there are no Dockerfiles for the backend or frontend, which run natively on Python 3.12 and Node 22. The full sequence was rehearsed end to end against a scratch database, so the README is accurate as written.

Critical step
python scripts/ingest_knowledge_base.py is not optional. Milestones live in the database, and alembic upgrade head creates the table empty — skip the ingest and every screening returns “not enough information”.
Two DB paths
DATABASE_URL is the privileged signal role (migrations, login, admin cross-institution reads). TENANT_DATABASE_URL is the unprivileged signal_app role so RLS binds. They are not interchangeable and there is no fallback.
Provider keys
Not in .env. They are entered through the admin console and encrypted at rest, write-only — only the last four characters are ever shown again. A new CREDENTIAL_ENCRYPTION_KEY makes previously stored keys undecryptable, so on a fresh machine simply re-enter them.
Data
The database does not travel with the repository. Seed scripts rebuild the knowledge base, a synthetic tenant and an admin account — enough for a full working system. Real screening records would need a pg_dump.
